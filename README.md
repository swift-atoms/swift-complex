# Complex

Complex represents a number through real and imaginary scalar components. The scalar representation determines available arithmetic and its rounding behavior. Complex is independent of spatial coordinates, documents, and a particular elementary-function implementation.

Magnitude, squared magnitude, normalization, principal square roots, and integer powers use Swift binary floating-point facilities. The Euclidean norm scales by a binary exponent before squaring, uses fused addition, and applies the scale after the square root. This avoids spurious intermediate overflow and underflow; infinity dominates NaN in the norm. Results follow the scalar operations and do not promise bit identity with platform hypot or universal correct rounding.

Principal square roots have nonnegative real components. Signed imaginary zero selects the side of the negative-real-axis branch cut. Infinite imaginary inputs yield infinite real and imaginary magnitudes; infinite real inputs preserve their appropriate root axis. Integer powers use repeated squaring and reciprocals, including Int.min without negating it; exponent zero yields one, including for zero base. Floating-point arithmetic still governs overflow, underflow, and cancellation in multiplication.

Polar phase and construction require only Trigonometry.Circular. Complex exponentials and logarithms require circular trigonometry and Exponential. Hyperbolic and inverse functions additionally require hyperbolic scalar capabilities. The atom declares these requirements without supplying or importing a platform backend. Numeric supplies concrete platform conformances in the higher layer. The existing swift-complex-numeric-relaxed package owns the cross-concept relaxed-arithmetic adapters.

Logarithms use the principal atan2 argument. Zero has negative-infinite real logarithm, with signed zeros preserving the branch side. Real-axis exponentials retain imaginary signed zero. Exponential components are scaled before overflow; very small coefficients can leave one finite component even when the other overflows. Large hyperbolic arguments retain component signs and the representable imaginary decay of tanh. General roots select the principal root, negative degrees take reciprocals, and degree zero produces NaN components. These compositions inherit backend accuracy and use ordinary rounded scalar arithmetic; they are not arbitrary-precision symbolic functions.

Scalar and componentwise closeness use Tolerance's validated allowances. Euclidean closeness scales complex distances and lengths to avoid overflow-driven false matches. Equal infinities match; NaN and unequal infinities do not. Invalid allowances return false through the nonthrowing convenience APIs. Closeness does not define hash identity or Equatable conformance.

Tests include SDK reference backends only inside test targets, principal-branch fixtures, extreme exponents, signed zero, subnormals, and half-precision operations without any elementary-function conformance. Inverse-function behavior across every exceptional complex input has not been exhaustively validated; this remains a numerical-review item rather than a correct-rounding or comprehensive C99-conformance claim.
